01

Trade the surprise, skip the rest

Most market news is either noise or already expected: CPI prints, Fed meetings, earnings. By the time it lands, the move has happened. The edge is in the rare, unscheduled shocks: an exchange hack, a protocol exploit, enforcement against a named token, a first-ever treasury sale.

So the bot is built to say no. It reads every post from four news channels, and the expectation is a handful of trades a month. Every decision, including every skip, is logged with its reason.

02

From post to position in seconds

The model call and the market data fetch run in parallel, so by the time Haiku has answered, the price context is already there. Hover or tap each stage.

03

Saga memory

News arrives in pieces. The first headline moves the market; the confirmation ten minutes later doesn't. Without memory, a bot would trade the same story three times.

Every post is assigned to a saga, a running story with its own summary and the moves it has already caused. The model is told what each saga has already done, and code enforces one trade per saga. If a story is denied or resolved, any open position on it is closed.

04

Only enter if it's still worth it

The model estimates how far the price should move. Code then works out the worst price it can still enter at and keep a minimum reward-to-risk. If the market has already gone past that price, the trade is skipped as priced in.

Emax = (T + Rmin·S) / (1 + Rmin)
S · last 1-minute close before the post arrived (the pre-news price)
T · target: S moved by the model's expected %
Rmin · minimum reward-to-risk to accept
Emax · the order is an immediate-or-cancel limit at this price
05

The stop sits at the pre-news price

If the news was real, price shouldn't go back to where it was before the post. If it does, the thesis is wrong. So the stop goes at S, widened only if that's inside normal 1-minute noise.

Size comes from the stop: risk a fixed amount, divide by the stop distance. Once the trade is up by the amount risked, the stop moves to breakeven; once it is up twice that, the stop starts trailing.

07

Hard to blow up

The model proposes; code decides. Scheduled macro releases, blackout windows around them, already-traded sagas, daily loss limits and cooldowns are all hard vetoes in code. Invalid JSON, a refusal or a timeout means no trade.

ModeWhat happens
log_onlyLive mainnet data, fills simulated against the live order book, no orders. The default.
testnetReal orders on Hyperliquid testnet.
liveReal orders. Refuses to start without an explicit confirmation phrase in the config.

It trades through an API wallet that can't withdraw, and refuses to start if given the main wallet's key. A KILL file or a /halt message stops new entries instantly. 79 automated tests cover each stage, from ingest to execution.

08

What's next

Keep it running and keep this log up to date. Every loss so far has been capped at the planned stop, so the next thing I'm studying is whether the losing trades share a pattern the vetoes could catch, without overfitting to a few weeks of data.
